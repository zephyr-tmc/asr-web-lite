# 文稿工作室

在启动本地应用后打开 `/workspace`，或从首页进入。保留原有录音上传与 TXT 下载。

## 使用

1. 导入文字；或者先转写录音，完成后点击任务中的“总结／分析”。
2. 查看文稿并按需校对。有音频及时间段的文稿可以点击引用回听；旧 TXT 和纯文字不编造时间戳。
3. 在“模型设置”填写连接名称、服务地址、模型名称与可选 API 密钥。
4. 选择要点总结或结构分析、篇幅，点击生成。原始音频仍在本机，仅发送当前所选文稿到配置的模型服务。
5. 核对引用，编辑并保存成果，可复制或导出 Markdown。历史成果可切换，原始文稿和成果分别保存。

## 模型兼容范围

首个适配器支持非流式 Chat Completions 兼容 JSON HTTP 接口，使用 `model` 和 `messages` 字段，从 `choices[0].message.content` 读取文字。可填完整的 `/chat/completions` 地址，也可填以 `/v1` 等路径结尾的基址，应用追加 `/chat/completions`。示例：`http://127.0.0.1:11434/v1`。服务中必须存在所填写的模型。

这不等于兼容所有厂商或所有模型；需要模型按提示返回 JSON 格式的概述、观点和引用。模型不遵循格式、回复被截断时，页面显示错误并保留既有资料。协议依据参见 [Chat Completions 接口文档](https://developers.openai.com/api/reference/resources/chat)。不绑定指定厂商，不内置付费服务或用户密钥。

远程地址要求 HTTPS；HTTP 仅用于 localhost、127.0.0.1 或 ::1。重定向不会自动跟随，避免将密钥发送到另一个地址。本机 API 不接受跨来源写入或非回环 Host；本版本仍是个人桌面应用，不是公网多用户服务。

密钥仅在应用服务进程内存中保留，重启后重新填写；前端不保存密钥，GET 接口不返回密钥，数据库与成果不包含密钥。连接地址与模型名保存在本机。更换服务地址会清除此前密钥；相同地址留空可沿用本次密钥。

## 资料与任务

`workspace.sqlite3` 与原有 `tasks.json` 放在相同应用数据目录。数据库保存导入文稿、校对版本、生成任务、输入快照和成果；音频文件仍由原来的上传目录保存。任务记录截断不会删除已导入工作室的文稿和成果。没有自动删除或上传全部资料的操作。

生成在独立于 ASR 的两工作线程队列运行，最多接收 8 个尚未退出的生成调用。失败后可手动重新生成；不自动重复收费请求。取消停止本地等待与结果写入，上游服务可能仍在处理或计费。服务重启后未完成的任务标为失败，可重新生成。

单次生成最多 32,000 字符；更长文稿需分段处理，应用不会静默截断。引用仅核对段落 ID 是否存在，不能保证模型推理或事实解释正确。文稿校对后旧成果标记输入版本；引用打开该成果使用的原文快照。

## 开发验证

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m unittest discover -s tests -v
```

无需模型权重即可运行工作室接口测试。Whisper 真实音频推理、第三方模型质量和平台安装包仍需各自测试。测试使用临时目录和受控回复，不包含个人录音或有效凭证。

Mac 与 Windows 共用仓库根目录下的 `asr_workspace/` 和 `app/static/`；Windows 的 Python 入口与打包 spec 保留平台路径处理。运行或构建 Windows 源码需完整仓库，不能只复制 `windows/` 子目录。

## 扩展

已审核的交互与视觉原型保存在独立的[设计参考分支](https://github.com/zephyr-tmc/asr-web-lite/tree/design/summary-prototypes-20261031/design)，不包含在正式页面。正式版采用成果阅读布局。

`asr_workspace/provider.py` 是文本生成适配器，`service.py` 管理版本与任务，`routes.py` 提供本机 API。后续模型协议可增加独立适配器。语音陪练、OCR、宣传物料与 PDF 不在这一版中；生产页面没有原型布局切换条和预设生成结果。
